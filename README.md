# 妮姬 OCR · 国服装备采集

从《妮姬：胜利女神》**国服**客户端的屏幕上，自动读取每个角色的**装备强化等级**与 **T10 词条（名称 + 数值）**，输出成 JSON 表，供下游工具计算资源投入优先级。

全程只截图 + OCR，**不读写游戏文件、不注入进程**。

更新记录见 [CHANGELOG.md](CHANGELOG.md) —— 记的是使用者视角的「这次更新你需要注意什么」，
升级前尤其值得看一眼那里的「变更」栏。

---

## 与上游项目的关系

本项目的起点是 [`arkz-tech/nikke-ocr`](https://github.com/arkz-tech/nikke-ocr)（英文全球服版，已归档）。

需要说明的是：**本项目在实现上没有复用上游任何代码。** `collect_cn.py`、`correct_gui.py`、
`build_icon_templates.py` 三个脚本（共约 3800 行）未 `import` 上游任何模块；OCR 引擎从
EasyOCR 英文模型换成了 RapidOCR 中文模型，页面坐标、状态判据、数据源全部重写。

之所以本地开发目录里还留着上游的 `src/` 等文件，只是因为当初就地在这个副本里开发 —— **那些文件本项目一个都用不到，也不在本仓库内**。你在 GitHub 上看到的这个仓库，只包含本项目自己的文件。

在此感谢上游项目提供的思路起点。

## 输出长什么样

`output/cn_collect.json`，顶层 `{"角色": [...]}`，每个角色一行。真实示例（节选）：

```json
{
  "姓名": "德雷克",
  "战力": 185448,
  "头": {
    "等级": 3,
    "词条": [
      { "名称": "攻击力增加", "数值": 0.0547 },
      { "名称": "未获得效果", "数值": 0 },
      { "名称": "防御力增加", "数值": 0.104 }
    ]
  },
  "甲": { "等级": 3, "词条": [ ... ] },
  "手": { "等级": 1, "词条": [ ... ] },
  "脚": { "等级": 0, "词条": [ ... ] }
}
```

四个槽位固定为 **头 / 甲 / 手 / 脚**，每个槽有 1 个强化等级（`0`~`5`）+ 3 个词条位。

**三个最容易踩的语义坑**（完整规格见 [`数据说明.md`](数据说明.md)）：

- **数值是小数，不是百分数**。`0.0547` 就是 `5.47%`。
- **`未获得效果` ≠ 缺失**。它表示「这是 T10 装备，但这个词条位是空的」。而等级与三个词条**全是 `null`** 才表示 **T9** —— T9 装备页上根本没有「改造装备效果」那一整块。
- **3 个词条位可独立锁洗，不是顺序填充**。经常出现「第 1、3 条有、第 2 条空」，不要按顺序读成「只有 1 条词条」。

9 个规范词条名（固定用游戏内全称）：`攻击力增加`、`防御力增加`、`暴击率增加`、`暴击伤害增加`、`命中率增加`、`最大装弹数增加`、`蓄力速度增加`、`蓄力伤害增加`、`优越代码伤害增加`。

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 |
| 游戏分辨率 | **1920×1080**，窗口全屏 |
| 显示缩放 | **100%** |
| Python | 3.10+（Windows 官方版，自带 tkinter） |
| **权限** | **必须管理员运行**（见下） |

> **为什么必须管理员？** 游戏本体以管理员身份运行。Windows 的 UIPI 机制会**静默丢弃**普通权限进程发往高权限窗口的模拟鼠标事件 —— 表现是脚本不报错，但点击完全没反应。`启动采集.bat` 会自动请求提权，不用手动开管理员 cmd。

## 使用

### 方式一：`启动采集.bat`（推荐）

双击运行，自动提权，**直接打开界面**（没有菜单了）。往后全在这个窗口里：

```
[采集…]   跑一次扫描。「增量」填个数、从当前角色往后重扫几个；「全量」扫到最后一个角色。
          两者**结果一样**：都产出补丁，跑完**自动接上合并**，不需要再去开别的程序。
双击单元格  改名字 / 战力 / 装备
[保存 JSON] 写盘
[合并补丁]  手动合并（正常情况下用不到，采集跑完已经自动并了）
```

> **为什么没有菜单了**：采集、合并补丁、校正数据本来是同一件事的三段，以前被拆成
> 控制台菜单的 `[1]`..`[6]` 加两个脚本，得自己记住「跑完命令行还要去图形界面点合并」。
> 现在合并这一步在采集结束时自动发生，补丁的**每一条都会列进合并窗**（图标唯一确定的
> 已经替你选好、标绿），一眼扫过、要改就地改。

> 界面里点「采集」时会先检查管理员权限：游戏是管理员运行的，普通权限发出的模拟点击会被
> 系统静默丢弃（不报错，就是点不动）。没提权会当场告诉你，而不是让你干等半小时。

> 诊断项（离线验证 / 检查页面状态 / 校验基线）留在命令行，见「方式二」。
> 离线验证需要根目录有 `ps.png` / `equipment.png` 标定截图。本仓库**不含**这两张图（游戏实拍含账号信息，已从版本控制排除），请用 `--ps` / `--eq` 指向你自己的截图。

### 方式二：命令行

日常用不到 —— `启动采集.bat` 更省事。这些是脚本化 / 排查时用的。

```bat
python correct_gui.py                :: 打开界面（采集、合并、校正都在里面）
python collect_cn.py                 :: 只采集，不开界面（5 秒倒计时，切回游戏）
python collect_cn.py --max 6         :: 从当前角色起采 6 个（采满即停，不再多翻一页）
python collect_cn.py --max 3         :: 增量重扫 3 个（结果写 output/cn_patch.json）
python correct_gui.py --merge-preview:: 干跑看一眼补丁会怎么合并（不写文件）
python collect_cn.py --offline       :: 离线验证
python collect_cn.py --check-state   :: 页面状态检查
```

**采集永远只产出补丁**，`--max N` 只是范围：小就是增量重扫，大到几百就是全量。主数据
（`output/cn_collect.json`）只有界面里的「合并」会写，采集进程一个字节都不碰它。

| 参数 | 说明 |
|---|---|
| `--offline` | 用本地截图模拟，不依赖 pyautogui |
| `--ps PNG` / `--eq PNG` | 指定标定截图路径（默认 `ps.png` / `equipment.png`） |
| `--max N` | 从当前画面起最多采集 N 个角色。小 = 增量重扫，大 = 全量（遇 LV.1 自动停） |
| `--save-shots` | 每页截图存 `output/shots/`（调试用，**很占磁盘**：单张 1.7MB × 角色数 × 5） |
| `--check-state` | 只跑页面状态分类器 |
| `--replace` | ⚠️ **逃生口**：归档后用本次结果**整个替换**主数据。只有换号 / 砍掉重练才用，界面不可达，也不能和 `--patch` / `--as` 同时给 |
| `--patch` | 兼容别名。**不写它也是这个行为**（结果写 `output/cn_patch.json`，主数据不动也不留底） |
| `--as "甲,乙"` | 按扫描顺序断言身份。**高级逃生口，日常不用** —— 它要手打角色名、打错还会中止整轮扫描；现在身份由图标自动定，定不下来的那几条在界面里选 |
| `--no-icons` | 关掉「用信息页那四个图标独立定名」。逃生开关，正常情况下不用它 |

### 姓名是怎么定的（图标级联）

角色名读的是游戏里的**滚动横幅**，截帧天然会截断 —— 实测约四成读错，而且最险的一种错是
「截断后**恰好等于另一个真实角色**」，那种错在 `correct_gui` 里是**零告警**的（名字在图鉴里
就返回「无问题」），会静默把别人的装备并到另一个人头上。

所以每采一行还会顺带读**信息页下方那四个静态图标**（属性 / 武器 / 职业 / 企业，逐像素稳定，
整轮约 1 毫秒，不额外截图），拿这四维去图鉴里筛人：

| 情形 | 处理 |
|---|---|
| 四维在图鉴里**唯一命中**，且名字有图鉴候选 | **采用图标定的人**（日志写明「按图标定为 X」） |
| 四维 + 姓名候选**交成唯一** | 采用（两路证据互相印证） |
| 交集唯一但**就是 OCR 名本身**而四维不唯一 | **不改名**并告警 —— 图标并没排除别人，记成「图标确认」是假证据 |
| 四维唯一命中，但 OCR 名在图鉴里**连候选都没有** | **不改名**并告警 —— 可能是国服特供（如 `婴宁`），也可能是读崩了，两者分不开 |
| 图标认不出 / 交不出唯一 | 保持 OCR 原名并告警 |

模板库是 `docs/icon_templates.png`（20 个值，从 31 张真实截图聚类取中位数生成）。
**游戏更新了那四个图标的美术资源**时，图标会开始报「认不出」，用新截图重跑
`python build_icon_templates.py` 重建即可，不用改代码。

`--as` 断言优先于人之外的一切；但**图标与断言不符会立即中止本次采集** —— 断言是按下标
一一对应的，错一格后面每一行都会错位，而图标的读数和下标无关，是唯一能当场戳穿它的证据。

### 方式三：增量重扫

升级了个别角色的装备后，不必为了拿一份新 JSON 再全量跑一遍 —— 只重扫那几个角色，
其余照旧，产出仍是**一份完整的角色表**。

**界面里**：点「采集…」→ 模式选「增量」→ 填扫几个 → 开始。先在游戏里手动翻到**第一个**
要重扫的角色、停在他的信息页，再点开始（有 5 秒倒计时给你切回游戏）。

**命令行**（脚本化时用）：

```bat
python collect_cn.py --max 3
```

- 结果写 `output/cn_patch.json`，**主数据 `output/cn_collect.json` 一个字节都不动**。
  错名/误判因此永远污染不了主数据 —— 合并前一律不碰它。
- **采集端没有跳转能力**（只有点「>>」逐格前进一条路），所以"从哪个角色开始"由你在游戏里翻。
- `--max N` 采满就停，**不会再多翻一页** —— 游戏停在原地，接着往下扫起点不会漂。
- **不用再手打角色名了**。身份由那四个图标自动定（见上一节）；补丁会把图标读数一起带上，
  合并时按它定人。

跑完**自动接上合并**（见下一节）。命令行跑的补丁，也可以在界面里点「合并补丁」手动并。

**「全量」和它不是两件事。** 模式选「全量」只是把范围放大到扫完为止（先翻到名单最上面）：
扫到的角色就地更新、没扫到的照旧、新角色追加 —— **不会替换整张表**。真正会整表覆盖的
只有 `collect_cn.py --replace` 那条逃生口（界面里没有入口）。

## 采集流程

开始前手动把游戏停在**第一个角色的总览页**，然后：

```
角色总览页
   └─ 点头像 ─▶ 角色信息页 ──── 读「名字 + 战力」
                   ├─ 点装备槽(头/甲/手/脚) ─▶ 装备页 ── 读「等级 + 3 条词条」
                   ├─ 再点同一槽关闭 ─▶ 回到信息页
                   └─ 点下一个槽 …
                └─ 翻页 ─▶ 下一个角色 …
```

- **每采完一个角色就落盘一次**（原子替换），中途 Ctrl+C 不丢已采集数据。
- 采集只写 `output/cn_patch.json`，**不碰主数据**。主数据 `output/cn_collect.json` 由界面里的
  合并写入，写之前会**自动改名加时间戳留底**（`cn_collect.<YYYYMMDD-HHMMSS>.json`）。
- **跑到名单末尾是怎么停的**：停止条件是「角色等级 = LV.1」（名册最后一个），`--max N` 再给个
  兜底上限。所以「全量」不用手动 Ctrl+C，扫到最后一个角色会自己停。
  换号 / 主数据要推倒重来时用 `--replace`（会整表替换，见上表）。

## 校正数据

OCR 做不到 100%。两类已知问题需要人工过一遍：

- **角色名读不全**：名字是一条带滚动动画的横幅，翻页后有时截到中间帧 —— 例如「拉毗：小红帽」读成「小红帽」、「索林：霜之旅票」读成「索林霜」。
- **词条数值偶发错读/漏读**：数值会落到相邻档位上（`11.81%` 读成 `11.11%`）。

```bat
python correct_gui.py
```

一张横向滚动的大表，双击单元格内联编辑。**按「要不要翻回游戏核实」把可疑行分三级配色**：

| 标记 | 底色 | 含义 |
|---|---|---|
| `▲` | 橙 | **必须看游戏**：姓名查无此人、战力缺失/违反降序、数值漏读 |
| `!` | 黄 | 靠已有信息能修：姓名有唯一候选、数值越档、重名 |
| — | 灰字 | 整槽未采集（信息性） |

- 姓名栏是下拉框，候选来自 `docs/chacters.json` 图鉴并按相似度排序 —— 点两下就行。
  **候选只提示、绝不自动改写**：图鉴里「索林」和「索林：霜之旅票」是两条独立词条，机器猜不出你要哪个。
- 数值栏也是下拉框，候选就是**该行词条名对应的那 15 档**（`11.11%` 这种写法，内部一律存小数）
  —— 不用记档位，也打不错。词条名漏读时没有档位可查，退化成全局并集并在状态栏提示一句。
- 按 `F3` 循环跳转到下一个可疑项，并自动横向滚到出问题的那一列。
- 保存**只写 JSON**，写回 `output/cn_collect.json`（同样先自动留底）。

配套命令：

```bat
python correct_gui.py --report         :: 不开窗，只打印校验基线
python correct_gui.py --roundtrip      :: 读入→原样写出→读回，验证零丢失
python correct_gui.py --merge-preview  :: 不开窗，只打印补丁会怎么合并（干跑）
```

### 合并补丁

采集（界面里的「采集…」，或命令行的 `collect_cn.py`）跑完后自动接上，也可以点顶部
「合并补丁 (N)」手动来。

**先分类，再全部列出来**：补丁里每一条都带着采集时读到的**图标四维**（属性/武器/职业/企业），
拿它去图鉴里查 —— 与姓名完全无关的机器证据。

| 情形 | 处理 |
|---|---|
| 四维在**你这张表**里唯一命中一行 | 预选好那一行（标绿「四维唯一」） |
| 四维在图鉴里认得出、但你表里没这个人 | 预选「追加为新角色」（猜错了也只是多一行，不会覆盖别人的数据） |
| 四维留下**多个**候选 | 展开提问 —— 这些角色的四维**故意相同**，图标在原理上分不开 |
| 四维在图鉴里**查无此人** | 展开提问 —— 国服特供（如 `婴宁`/`画皮`）属正常，也可能是图标读歪了 |
| 图标读不出来 | 展开提问（姓名只用来给候选**排序**，不足以自己拍板） |

**补丁的每一条都会出现在审阅窗里**，包括上面那两行「已经替你选好」的 —— 绿色标记只表示
「机器认为它定了」，下拉里选的是哪一行你照样看得见、改得动。想专挑要定的看，顶部切
「只看待确认 (N)」即可；**切筛选不会漏掉任何一条**（隐藏的条目照样会按预览值执行）。

> **为什么不干脆全自动**：以前图标唯一确定的那些会被**静默并掉**，窗口里根本不出现 ——
> 想核对或改一处就得去翻 JSON。现在它们只是「预选好」，不是「已经执行」。

> **姓名为什么不能自己拍板**：角色名读的是滚动横幅，截断后**可能恰好等于另一个真实角色**
> （`红莲：暗影` 截成 `红莲`）。「姓名精确命中」这种证据单独出现时不足以支撑自动合并，
> 必须有人看一眼。

窗口里每条还能勾：

- **空槽也覆盖**：补丁里为空、而旧行有值的槽，**默认保留旧值**并在块里标红。空到底是 T9 的真值
  （T9 本来就没词条，空是对的）还是这次没读到，光看补丁分辨不了 —— 确定是真 T9 才勾。
  预选的那些**一律保留旧值**，不会替你覆盖。
- 战力没读到（`null`）时同样保留旧值。

写入前主数据先自动留底；**合并后按战力降序重排**（游戏名册就是这个序，不重排会凭空造出一处
「战力违反降序」的假告警）。补丁文件在合并成功后自动改名留底（`cn_patch.<时间戳>.json`），
防止手滑再合并一次。

**合并从不删除行**：主数据里这次没扫到的行原样保留，只在扫到的那些上就地更新、以及追加新角色。

## 已知限制

- **必须管理员权限**，否则点击被系统静默丢弃（脚本不报错，但没反应）。界面点「采集」时会先检查。
- **分辨率锁死 1920×1080**，页面坐标按此标定。
- **长角色名可能读不全**（滚动动画中间帧）。现在由前面「姓名是怎么定的」那一节自动修掉大部分，
  但仍有两类必须人工看：**国服特供角色**（不在图鉴里，如 `婴宁`/`画皮`），以及
  **四维完全相同的角色**（同一角色的不同变体，如 `白雪公主`/`白雪公主：纯真年代`、
  `银华`/`银华：战术升级`、`艾玛`/`艾玛：战术升级` —— 图标在原理上分不开）。
  这两类在合并窗里**展开提问**（其余条目预选好、压成一行）。合并窗的默认筛选是「全部」，
  想专挑要定的看就切「只看待确认」。
  （图鉴 201 条里有 39 组四维相同的组合，所以撞上并不罕见；撞到你表里没有的那个人时也会弹。）
- **主数据里若有没校正过的错名，增量/全量合并可能追加出一行重复**。图标找出真名后要按名字
  回你表里找那一行，名字是错字就找不到 → 当成新角色追加。主界面本来就会把「图鉴查无此人」
  的行标成橙底，**合并前先把它们改对**即可；合并窗里「四维唯一 → 新角色」的绿色标记就是
  这类追加，一眼能扫到。整表替换（`--replace`）不会有这个问题，但它会丢掉没扫到的行。
- **词条数值偶发错读**（落到相邻档位）**或漏读**。词条表能挡掉「落不到合法档位」的错读，挡不住「落在别的档位」的，需人工核对。
- **游戏客户端更新若改动 UI 布局**，页面状态判据与坐标都要重新标定。
- 采集耗时噪声较大，同一份代码同一台机器实测可能相差近一倍，不要拿单个数字当精确值。
